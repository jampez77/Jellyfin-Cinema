# ScreenHarbour 0.2.37 — prerelease

**Fixes Playlists still appearing on Home after being hidden in Jellyfin's Home preferences.** Version 0.2.36 respected the saved exclusions, but Jellyfin stores the Playlists setting against a per-user view ID while Home Screen Sections renders the underlying folder ID. Those IDs are different.

ScreenHarbour now resolves that relationship on the server using Jellyfin's own user views. Both the saved view ID and its underlying folder ID are excluded. This works after renaming a library and on TV, where row headings may have no links. Re-enabling the library restores its row.

The new endpoint is read-only and limited to the authenticated account. Existing library exclusions, deliberately selected custom collection rows, account-specific caching and all saved settings are retained. No settings migration is needed.

## Update

## Validation

The issue was reproduced on the live server running 0.2.36.3: the Playlists checkbox was unchecked, its extra Recently Added row remained visible, and Music was correctly hidden. The saved playlist-view ID differed from the row's physical folder ID.

TypeScript, **217 unit checks** and **10 focused browser checks** passed. Browser coverage includes desktop and TV, headings without links, renamed libraries, restoring visibility, account changes and cached return visits. **469 server checks passed on each Jellyfin 10.10.7, 10.11.0 and 12.0.0 target**, including the reported playlist IDs, account/session authorization, unchanged preferences and actual HTTP serialization. The 10.10 checks used local runtime roll-forward. Installation on the live server and physical LG webOS testing remain pending.
