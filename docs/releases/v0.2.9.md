# Jellyfin Cinema 0.2.9 — prerelease

Custom Home collection rows now follow the same Jellyfin account between desktop and TV. This release also fixes Cinema profile switching leaving the current server on webOS and removes the delayed Cinema takeover during navigation. Install from the Jellyfin Cinema catalogue or the [v0.2.9 release assets](https://github.com/jampez77/Jellyfin-Cinema/releases/tag/v0.2.9), following the [installation guide](../server.md).

## Changes

- Row titles, collections, tabs, ranked artwork, item order and Home position sync through an authenticated per-user server endpoint. Existing browser settings migrate only when no server copy exists. A fresh TV cannot overwrite saved rows with an empty default; deliberate deletion remains authoritative. Concurrent edits receive a reload prompt instead of silently overwriting each other.
- Home keeps an offline cache and refreshes saved rows when opened, when the app regains focus and every minute while visible. Failed saves retain the editor draft and show an error. Native Jellyfin Home and Featured settings remain under those components’ control.
- During Cinema profile switching on webOS, Jellyfin still clears the outgoing session, query cache and native views. Its final public shell callback then opens the same server’s login route, preserving the web frame so the eligible passwordless login can complete. Normal native logout, protected profiles, eligibility and account policies are unchanged.
- Hash, Back and native view events establish Cinema styling and native-page masking immediately. Returning to a previously identified Collections or Recordings library reuses its account-scoped classification, avoiding another native-layout interval while checking the library type.
- During live video, exposed channel-up/down keys or commands step through the permitted guide lineup using Jellyfin’s native player. Held repeats, overlapping tuning and stale account/navigation requests are guarded. Other media, text fields and dialogs keep their native controls.

## After installing

Restart Jellyfin and fully close/reopen the clients. **Open Home once in the original desktop browser where you created your rows**, then open Home on the TV with the same account. This migrates the old browser-only settings to the server. Other accounts keep their own rows. The server copy wins when one already exists.

**LG programme +/− limitation:** LG documents these buttons as unavailable to webOS apps. Cinema handles channel events when a client delivers them, but cannot receive a key reserved by the TV. Use **Down → Channels** if the buttons do not reach Jellyfin. Page Up/Down are not remapped. See [LG’s key table](https://webostv.developer.lge.com/develop/guides/magic-remote) and [LG’s support response](https://forum.webostv.developer.lge.com/t/cannot-press-channel-up-down-to-trigger-an-event/18008).

## Validation

- All 312 browser checks passed, including cross-device migration, conflicts, deletion, offline recovery, webOS profile handoff, channel commands and immediate route ownership.
- All 137 unit/API tests and TypeScript checks passed.
- All 78 server verification assertions passed on each of Jellyfin 10.10.7, 10.11.0 and 12.0.0, including user/device isolation, concurrent migration, stale revisions, atomic persistence and Unicode size limits.
- All three installable packages built with zero compiler warnings or errors.

Browser checks use simulated server responses and audited Jellyfin Web sources. The webOS tests replay its public shell handoff, including a simulated document unload; the final package has not yet been tested on a physical TV or installed on the Mac mini.
