# Jellyfin Cinema 0.2.19 — prerelease

Returning to Home now uses the collection data already loaded during the current session. Streaming services and collection rows appear without waiting for another settings or membership request, and without replaying the full-screen loading animation. Settings, collection metadata and members refresh in the background.

The first Home load still uses the cinema animation while the rows assemble. Returning from a film, episode or streaming service preserves the selected card, collection tab and scroll position. Native Jellyfin's later focus restoration is handled without taking priority over new user input. Requests for the collection catalogue are also shared during initial construction instead of being repeated by overlapping renders.

Cached content lives only in memory for the current account. Switching accounts or servers, signing out, or destroying Cinema clears it. A full client reload starts a new session.

## Installation

Update from the existing Cinema catalogue, restart Jellyfin, then reload desktop Jellyfin and fully close/reopen the TV app.

## Validation

- TypeScript and all 176 unit/API tests passed.
- All 137 affected Home/provider browser tests passed, with the final catalogue change rechecked against 37 loading, refresh and return tests.
- Browser regressions verify that cached Home rows appear with preference and membership requests held indefinitely, without mounting a loader. They also verify background updates, account isolation, adding the first collection, and focus/scroll restoration after native Back navigation.
- No server behaviour changed. Packages are built for all three supported Jellyfin targets. The new build has not been installed or tested on the physical Mac mini/LG TV during development.
