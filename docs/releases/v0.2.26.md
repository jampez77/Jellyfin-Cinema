# ScreenHarbour 0.2.26 — prerelease

**Jellyfin Cinema is now ScreenHarbour: a cinematic interface for Jellyfin.** The independent name and new artwork follow [Jellyfin's third-party branding guidance](https://jellyfin.org/docs/general/contributing/branding/). ScreenHarbour is not affiliated with or endorsed by Jellyfin.

This release changes the public name, catalogue artwork, interface labels, documentation, repository and demo links. It does not introduce new features or change playback, collection or account behaviour. The README continues to state that the project is fully vibe coded, that the maintainer has not read or reviewed the code, and that use is at your own risk.

## Update your existing installation

In **Dashboard → Plugins → Repositories**, replace the old Jellyfin Cinema or TV Item Layout catalogue entry with **ScreenHarbour** and this URL:

```text
https://raw.githubusercontent.com/jampez77/ScreenHarbour/main/manifest.json
```

Update the existing plugin, restart Jellyfin, then reload desktop Jellyfin and fully close/reopen the TV app. Keep a compatible **File Transformation** plugin enabled. **Do not uninstall the plugin or add a second copy.**

| Jellyfin server | Plugin version |
| --- | --- |
| 10.10.7 | 0.2.26.1 |
| 10.11.x | 0.2.26.2 |
| 12.x | 0.2.26.3 |

The plugin GUID (`1a06b74f-7609-4af9-899d-430c9b5a52b1`), `Jellyfin.Plugin.TvItemLayout.dll`, `/TvItemLayout` API routes, script filename and `TvItemLayout_…` archive names remain unchanged. Browser storage keys, route parameters and server data directories under `jellyfin-cinema/` also retain their existing names. Saved collection rows, streaming-service selections and account settings continue to use those same identifiers; no settings migration or reset is needed. Playback history remains owned by Jellyfin.

The repository is [jampez77/ScreenHarbour](https://github.com/jampez77/ScreenHarbour), renamed in place so its existing releases are retained. Older catalogue entries keep their versions and checksums, with release links updated to the new repository path. Use the new [demo address](https://jampez77.github.io/ScreenHarbour/?layout=desktop&featured=0#/home); README screenshots are labelled as historical captures made before the rebrand.

## Validation scope

- Type checking, the frontend/static-demo builds and all 186 unit tests passed.
- The 475-scenario browser run initially passed 473 scenarios. The two failures passed targeted reruns under the normal configuration; the collection-refresh case also passed an isolated comparison with the previous bundle. No unrelated functional changes were made to address these timing-sensitive results.
- All 242 server checks passed against each target API. The 10.10.7 checks used .NET 9 runtime roll-forward because .NET 8 is not installed on the verification machine; the plugin itself remains compiled for .NET 8. The 10.11.x and 12.x checks used their installed .NET 9 and .NET 10 runtimes.
- All three packages compiled with the unchanged plugin identity. Catalogue verification preserved all 78 historical entries, changing only their repository URL prefix, and selected the correct new build for each ABI. Collection and provider storage identifiers were compared against the previous commit and remain unchanged.
- Desktop and TV branding was visually checked, including profile, login, loading and streaming-service settings screens.

This is a branding-only prerelease. Automated checks and browser fixtures do not establish real-server playback or physical TV compatibility. Physical Mac mini deployment and LG webOS remote testing have not been performed for this release.
