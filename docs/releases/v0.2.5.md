# Jellyfin Cinema 0.2.5 — prerelease

This update adds a TV profile menu, covers recording folders opened from Home, and gives the native music queue a larger cinematic layout. Install it from the Jellyfin Cinema catalogue or the [v0.2.5 release assets](https://github.com/jampez77/Jellyfin-Cinema/releases/tag/v0.2.5), following the [installation guide](../server.md).

## Changes

- In TV mode, the user avatar offers **Switch profile** and **Settings**. Profile switching uses Jellyfin’s own sign-out and user-selection flow. Existing password requirements still apply. Desktop and mobile keep the native avatar and account menu.
- The **Recordings** library tile on Home opens the Cinema recordings layout, including an empty recording folder. Browsing stays scoped to the selected recording folder. Ordinary libraries retain their native routes.
- The native music queue has a larger album-art and track-information layout, clearer playback controls and matching queue rows. Jellyfin continues to own playback, seeking, volume and queue actions.
- The [UK platform chart guide](../platform-trending.md#source-urls) lists the exact movie/show source links used by the optional streaming rows. These are JustWatch UK weekly charts supplied through MDBList; Home includes matching library titles in source-relative order.

## Validation

- 235 browser checks passed: the 230-test regression suite, including Featured, plus five checks against Jellyfin 12’s actual music-page template and styles. Music checks also cover narrow layouts, missing artwork, native controls, hidden/disabled states and desktop restoration.
- 87 unit/API tests, TypeScript checks, the client build and server integration checks passed.
- All three server packages built with zero warnings and errors.
- The recording-library route and native avatar/player markup were inspected on Jellyfin 12. The music layout was reviewed visually at wide and narrow widths.

This release has not yet been installed on that server or tested with a physical TV remote. The player checks exercise native markup with simulated playback callbacks; they do not establish real-server audio playback or hardware compatibility.
