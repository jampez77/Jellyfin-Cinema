# Jellyfin Cinema 0.2.7 — prerelease

Passwordless switching now recognises eligible accounts on Jellyfin 12, and the TV avatar opens a full-screen **Who’s watching?** chooser. Install from the Jellyfin Cinema catalogue or the [v0.2.7 release assets](https://github.com/jampez77/Jellyfin-Cinema/releases/tag/v0.2.7), following the [installation guide](../server.md).

## Changes

- **Passwordless switching on Jellyfin 12:** Jellyfin’s obsolete public password flags always report true, which prevented 0.2.6 from recognising passwordless accounts. Cinema now reads current eligibility from its server plugin and checks again immediately before signing out.
- **Who’s watching?** opens directly from the TV avatar, with large square profile artwork, names, a current-profile indicator and clear remote focus. Select your current profile or Back to return. Settings, Use login screen and the administrator’s Dashboard remain secondary actions. Desktop and mobile keep Jellyfin’s native account menu.
- Direct switching is limited to visible, enabled, non-administrator accounts using Jellyfin’s default authentication provider with no password and permitted on the current device/network. Other profiles say **Sign in** and retain native authentication. No accounts, passwords or permissions are changed by this update.
- The eligibility endpoint requires a signed-in user/device session, rejects API keys, returns only eligible IDs and is not cached. Missing or incompatible endpoints fall back to native sign-in. Cinema makes one normal authentication request after native logout completes; it does not probe accounts, retry failed authentication, save passwords or retain extra account tokens.
- Cancelling, changing pages/accounts/servers, or receiving a delayed response cannot silently adopt a different profile. Existing native logout and session-cleanup safeguards remain in place.

To switch both ways without entering a password, both viewing accounts must be eligible and passwordless. Keep the administrator account separate and password-protected. The server always makes the final sign-in decision, including if a password or policy changes during a switch.

## Validation

- All 267 browser checks passed, including 19 profile-switcher checks, the actual Jellyfin 12 login controller, Featured and the active ElegantFin stylesheet. The chooser was reviewed at TV and narrow widths.
- All 114 unit/API tests, TypeScript checks and the client build passed.
- All 55 server assertions passed against each supported Jellyfin target, including 22 eligibility assertions. The 10.10.7 target compiled for .NET 8; its checks ran on .NET 9 using runtime roll-forward because this machine has no .NET 8 runtime.
- All three release packages built with zero compiler warnings or errors.

This release has not yet been installed on the Mac mini or tested with a physical TV remote. Browser switching checks simulate server responses; they do not establish a live-server session handover.
