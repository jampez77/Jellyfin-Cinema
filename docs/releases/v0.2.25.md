# Jellyfin Cinema 0.2.25 — prerelease

Partly rewatched movies and episodes now offer **Resume** at the saved position alongside **Play from beginning**, even when Jellyfin retains its watched flag from an earlier viewing. Cinema shows these items as in progress, and **Mark watched** remains available to deliberately complete them. Cinema does not clear saved progress or viewing history when opening an item or requesting playback. Jellyfin continues to update playback history normally; its underlying historical watched flag is preserved.

**Continue watching** in Cinema's Movies layout now has a playback-progress bar along the bottom of each thumbnail. The same card treatment applies to other resumable items in Movies and TV Shows. Episode thumbnails, the in-player browser and **Ends at** also use the current saved position ahead of an earlier watched flag.

Streaming-service collection selections are saved per Jellyfin account, so each profile can have different choices. Fresh server-host, session and device tests confirm that explicit collection IDs survive restarts. An unreadable settings file now returns an error instead of appearing to contain no settings, allowing the client to retain its last confirmed configuration.

## Installation

Update through the existing Cinema catalogue, restart Jellyfin, then reload desktop Jellyfin and fully close/reopen the TV app.

## Validation

- TypeScript, all 186 unit/API tests and 116 affected browser regressions passed.
- New desktop and TV-layout cases cover partial rewatches with a retained watched flag, current progress bars, saved Resume and zero-position restart requests, finish times, failed playback preserving progress, and explicit watched actions. All four new detail/library cases fail against the previous bundle and pass with this release.
- In-player coverage verifies a partly rewatched film shows its actual progress and resumes at its saved position. Completed films with no new position still start from the beginning.
- All 242 server verification assertions passed on each supported Jellyfin target, including fresh-host restart/account isolation and recovery after an unreadable settings path. The 10.10.7 verification host used .NET 9 roll-forward; its package still targets .NET 8.
- Progress bars were visually checked in desktop and TV layouts. Physical LG webOS testing remains pending.
