# ScreenHarbour 0.2.36 — prerelease

**Home now respects Jellyfin's library exclusions for the extra per-library rows added by Home Screen Sections.** A library such as Music could be unchecked in Jellyfin's Home preferences yet still appear as “Recently Added in Music” at the bottom of Home. Home Screen Sections generates those additional rows independently of the native exclusion list.

ScreenHarbour now reads the signed-in account's saved exclusions and applies them to those rows on both desktop and TV. Matching uses the library's stable ID, so renaming a library does not break the setting. Excluded rows occupy no space and do not delay Home while their background requests finish. Remote focus moves to a remaining visible control if the currently selected row becomes excluded.

Re-enabling a library's **Display in home screen sections such as Recently Added Media and Continue Watching** checkbox restores its extra row. Preferences refresh on Home visits, when the page regains focus and during normal polling. Successful preferences are cached for the current account, keeping return visits fast and retaining exclusions through temporary connection failures.

My Media shortcuts, native Jellyfin sections and explicitly chosen collection rows retain their existing behavior. The compatibility rule applies to Home Screen Sections' identifiable per-library Recently Added rows; aggregate third-party sections without a single-library identity remain controlled by their plugin. No saved settings are rewritten. Seasonal groups, shuffle and all previous features are retained.

## Update

Update **ScreenHarbour**, restart Jellyfin, then fully reload the browser or close and reopen the web-based TV client. Keep **File Transformation** enabled. No uninstall or settings migration is needed.

## Validation

TypeScript, **217 unit checks**, and **115 browser checks** passed; 20 optional external-source browser checks were skipped because their audited checkouts were unavailable. **446 server checks passed on each Jellyfin 10.10.7, 10.11.0 and 12.0.0 API target.** The 10.10 checks used local runtime roll-forward.

The issue was reproduced on the live account, including confirmation that Music was excluded in a freshly loaded Jellyfin preferences page. Automated checks cover stable-ID matching, desktop and TV, asynchronous row insertion, saved preference changes, cached returns, account changes, focus recovery and hidden pending rows. The fix has not been installed on the live server or tested on a physical LG webOS TV during this release work.
